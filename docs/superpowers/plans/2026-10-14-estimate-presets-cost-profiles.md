# Estimate Starting Points and Cost Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make estimate starting points reversible and horizontally navigable, add consultative service archetypes such as risk assessment, and deliver user/global commercial profiles with auditable pricing and printable export.

**Architecture:** Keep presets server-owned and the estimate calculation authoritative in the NestJS API. Extend catalog entries with an explicit calculation basis so functional archetypes remain measured in function points while consultative services are measured in hours. Resolve one effective commercial profile per user, snapshot every applied parameter into each estimate, and keep historical reports immutable.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind CSS, NestJS 11, Prisma 6, PostgreSQL on Supabase, Vitest, native browser print/PDF.

## Global Constraints

- Do not use `window.confirm`, `window.alert`, or another browser-native prompt for preset changes.
- Switching starting points may replace the complete board, including custom items, after confirmation in an application-styled dialog.
- Deselecting the active starting point clears both its association and the complete estimate board.
- The preset rail supports previous/next buttons, touch/trackpad scrolling, keyboard focus, and reduced-motion preferences without a carousel dependency.
- Treat risk assessment as a consultative service measured in hours, not as an artificial IFPUG function-point count.
- A global commercial profile, when active, replaces the complete user profile; there is no field-by-field mixture.
- Only `admin` and `super_admin` users may edit or activate the global profile.
- New estimates snapshot the effective profile and calculation result; previously saved estimates never change when profiles change.
- Use additive markup terminology: risk is applied to labor cost, profit markup to labor plus risk, and tax to the resulting commercial subtotal.
- Existing estimates migrate with zero profit markup, zero tax, zero service hours, and their current final prices unchanged.
- The profile export contains all effective commercial parameters and is explicitly generated by the user before it can be sent to a client.
- Do not expose a Supabase secret/service-role key to the Vite application; all data continues through the authenticated NestJS API.

## Decision Gates Assumed by This Plan

1. **Preset deselection:** clear `presetKey` and every item currently on the estimate board.
2. **Preset switching:** request confirmation in an accessible PriceFunc-styled dialog, then replace the complete board; never use a browser-native prompt.
3. **Initial new starting points:** add `Landing page` and `Avaliação de riscos`; keep the preset registry data-driven so later additions require only one backend definition.
4. **Risk assessment model:** add a service calculation basis with detailed activities and estimated hours.
5. **Global precedence:** when active, every user estimate uses all global values; user values remain stored and become effective again when global mode is disabled.
6. **Pricing order:** `labor -> risk -> profit markup -> tax`.
7. **Export visibility:** the printable commercial-profile report shows hourly rate, productivity, risk, profit markup, tax, calculation order, scope, and update date.

Execution must not begin until the product owner approves these seven decisions or replaces any of them explicitly.
